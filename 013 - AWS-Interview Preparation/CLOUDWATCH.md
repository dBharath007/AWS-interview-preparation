### 1. What is Amazon CloudWatch?
Amazon CloudWatch is a monitoring and observability service that provides insights into your AWS resources and applications by collecting and tracking metrics, logs, and events.
## What is Amazon CloudWatch?

**Amazon CloudWatch** is a monitoring and observability service provided by Amazon Web Services that helps you monitor the performance, health, and operational status of your AWS resources and applications in real time. It collects **metrics, logs, and events** from different AWS services and gives you insights through dashboards, alarms, and automated actions.

In simple terms, CloudWatch acts like the **“health monitoring system” of your AWS infrastructure**. It continuously tracks resources such as Amazon EC2 instances, Amazon RDS databases, Amazon S3 storage, and AWS Lambda functions. By analyzing these metrics, CloudWatch helps administrators and developers quickly detect issues like high CPU usage, application errors, or system failures before they affect users.

CloudWatch works by automatically **collecting metrics** from AWS services and optionally from custom applications. These metrics represent numerical data such as CPU utilization, memory usage, network traffic, or request counts. Users can visualize this information using **CloudWatch dashboards**, which provide graphs and statistics about system performance. Additionally, CloudWatch allows you to create **alarms** that trigger notifications or automated actions when certain thresholds are exceeded, such as sending alerts through Amazon SNS when CPU utilization becomes too high.

Another important feature of CloudWatch is **CloudWatch Logs**, which allows you to collect and store log files from applications, servers, and AWS services. These logs can be searched and analyzed to troubleshoot issues or track system behavior over time. CloudWatch also supports **event-driven automation**, where events from AWS services can trigger workflows or Lambda functions to respond automatically.

Overall, Amazon CloudWatch is a **centralized monitoring service** that helps organizations maintain system reliability, improve performance, and quickly identify operational problems in their AWS environment.

## What types of data does Amazon CloudWatch collect?

The main types of data collected by CloudWatch are **metrics, logs, and events**.

**Metrics** are numerical measurements that represent the performance or usage of AWS resources over time. CloudWatch automatically collects these metrics from services such as Amazon EC2, Amazon RDS, Amazon S3, and AWS Lambda.

### 3. Events

CloudWatch captures **events** that represent changes or actions happening within AWS resources. These events are part of an event-driven architecture and help automate responses to system changes.

For example, if an EC2 instance changes its state from running to stopped, CloudWatch can capture that event and trigger automated actions such as sending notifications through Amazon SNS or invoking a Lambda function.

In addition to default metrics collected by AWS services, CloudWatch allows users to publish **custom metrics** from their own applications. This enables organizations to monitor application-specific data such as number of active users, application response time, or business transaction counts.

### 5. How can you collect custom metrics in Amazon CloudWatch?
You can collect custom metrics in CloudWatch by using the CloudWatch API or SDKs to publish data to CloudWatch using the `PutMetricData` action.

## How can you collect custom metrics in Amazon CloudWatch?

Custom metrics in **Amazon CloudWatch** allow you to monitor application-specific data that is not automatically collected by **Amazon Web Services**. While AWS services like Amazon EC2 or AWS Lambda send default metrics automatically, sometimes you need to monitor your **own application data**, such as request processing time, number of active users, or queue length. This is where **custom metrics** are used.

Custom metrics are collected by **publishing data points to CloudWatch** using different methods.

### 1. Using the AWS CLI

One common way to send custom metrics is by using the **AWS Command Line Interface (CLI)**. The CLI provides the `put-metric-data` command, which allows you to send metric values directly to CloudWatch.

Example:

```bash
aws cloudwatch put-metric-data \
--namespace "MyApplication" \
--metric-name ActiveUsers \
--value 120
```

In this example, a custom metric named **ActiveUsers** is sent to CloudWatch under the namespace **MyApplication**.

### 2. Using AWS SDKs

Applications can also send custom metrics programmatically using **AWS SDKs** such as Python (Boto3), Java, or Node.js. This method is commonly used when applications need to report metrics continuously.

For example, a Python application can send a metric to CloudWatch whenever a user logs in or when a transaction occurs.

### 3. Using the CloudWatch Agent

The **CloudWatch Agent** can be installed on servers such as **Amazon EC2** instances or on-premise machines. This agent collects system-level data like memory usage, disk usage, and custom application metrics and sends them to CloudWatch automatically.

This is especially useful because **default EC2 metrics do not include memory usage**, so the CloudWatch agent can be configured to collect it.

### 4. Using Logs and Metric Filters

Another method is through **CloudWatch Logs metric filters**. If your application logs certain events, CloudWatch can scan those logs and convert specific patterns into metrics.

For example, if an application log contains the word **ERROR**, CloudWatch can count how many times it appears and create a metric representing the number of errors.

### 5. Using Embedded Metric Format (EMF)

Applications can also send structured logs using the **Embedded Metric Format**, which CloudWatch automatically converts into metrics. This is commonly used with services like **AWS Lambda**.

### 6. What are CloudWatch alarms?
CloudWatch alarms allow you to monitor metrics and set thresholds to trigger notifications or automated actions when specific conditions are met.

## What are CloudWatch Alarms?

**CloudWatch Alarms** are a feature of **Amazon CloudWatch** that automatically monitor CloudWatch metrics and trigger actions when a specified threshold is reached. They help administrators detect performance issues and respond quickly by sending notifications or performing automated actions.

A CloudWatch alarm continuously observes a **specific metric** over a defined time period. These metrics can come from AWS services such as **Amazon EC2**, **Amazon RDS**, **Amazon S3**, or even custom metrics created by applications. When the metric crosses the configured threshold, the alarm changes its state and triggers a predefined action.

For example, an administrator might create an alarm that monitors the **CPU utilization of an EC2 instance**. If the CPU usage exceeds 80% for a certain number of minutes, CloudWatch will trigger the alarm. Once triggered, it can send a notification using **Amazon SNS**, execute an automated scaling action, or trigger an **AWS Lambda** function to perform corrective tasks.

CloudWatch alarms operate in **three main states**. The first state is **OK**, which means the monitored metric is within the normal threshold. The second state is **ALARM**, which means the metric has crossed the defined limit and requires attention. The third state is **INSUFFICIENT_DATA**, which occurs when there is not enough metric data available to determine the alarm state.

These alarms are very useful in DevOps environments because they enable **proactive monitoring and automated response**. Instead of manually checking resource performance, CloudWatch alarms ensure that teams are notified immediately when something goes wrong, allowing them to maintain system reliability and performance.

CloudWatch Logs organizes log data into three main components. The first is a **log group**, which is a collection of logs that share the same source or purpose. Inside a log group are **log streams**, which represent sequences of log events generated by a specific resource, such as a particular EC2 instance or Lambda function. The individual records within the stream are called **log events**, which contain the actual log messages along with timestamps.

Using CloudWatch Logs, engineers can **search and filter log data** to identify errors or unusual behavior in applications. It also supports **metric filters**, which allow specific patterns in logs—such as the word “ERROR”—to be converted into CloudWatch metrics. These metrics can then be used to create alarms that notify administrators when issues occur.

CloudWatch Logs can also trigger automated actions. For example, when a specific log pattern appears, CloudWatch can activate a notification through **Amazon SNS** or invoke an **AWS Lambda** function to respond automatically.
